# 規則

検出器が数える規則を、規則 ID ごとの節で記述する。見出しは指摘の規則 ID から引ける形にし、検出器のコードは説明を持たずにここの見出しを参照する。

## 層と採点

規則は 6 つの層に分かれ、層が重みと計数の条件を決める。

| 層 | 規則 | 数えるもの | 性質 |
|---|---|---|---|
| 構造 | S01〜S06 | 無生物主語と発話動詞、文頭の指示代名詞、足場語、書き手の明示、否定と肯定の対句、文頭の接続詞の連打 | 指示でもモデルでも残る |
| 語彙 | L01〜L03 | 慣習語からの逸脱。和語化の側と漢語・逐語訳の側 | 語リストに依存する |
| 密度 | D01〜D03 | 短文の連打、述語を持たない断片文、無根拠の緩和 | ジャンルで変動する |
| レジスター | R01〜R03 | 口語の混入、身体的な比喩、敬体と常体の混在 | 敬体率で適用を切り替える |
| 定型句 | F01〜F06 | 回答の締め、太字、2 倍ダッシュと矢印、空虚な強調、迂言 | 表層で確実に検出できる |
| 語種 | G01 | 文末の述語に占める和語動詞の割合 | 文書単位の割合 |

癖には二つの層がある。語彙と装飾と分量の層は、指示とモデルで両極に変動する。指示の無い Sonnet は漢語と冗長の側に、簡潔の指示を受けた Opus と Fable は和語と断片文の側に逸脱する。どちらも日本語話者の文から外れ、方向が逆である。構造の層は指示とモデルに依存しない。文書や型を語り手に立てる形、文頭で前の文を受けて評価する形、足場語、書き手の明示、場面によらない一つの声は、どの観察にも共通して出現した。したがって構造の層（S）を最優先で直し、語彙の層（L）は両極を同時に検出する。簡潔の指示だけを与えても、和語の断片文という別の不自然さに変わるだけである。

点は、指摘 1 件に規則ごとの重みを掛け、日本語の文字数 1000 字あたりに正規化した値である。層ごとの小計と規則ごとの件数も併せて出力する。日本語の文字数が 300 字に満たない入力では、1 件の指摘で点が数十動き、割合で評価する意味が無い。この下限に満たない入力は件数で判断し、構造か語彙の層の指摘が 1 件でもあれば超過とする。密度・レジスター・語種の文書単位の規則は、下限以上の入力にだけ適用する。

悪い例はコードスパンか表に置く。検出器はコードスパンの中身を採点の対象から外すので、規則集が自身の例を数えることはない。

## S01 文書・型・検査を語り手にしない

人を表さない名詞に格助詞の「が」が続き、6 語以内に語リストの発話動詞（`述べる`、`名乗る`、`名指す`、`語る`、`答える`、`主張`、`宣言`、`約束`、`教える`、`知らせる`、`訴える`）が現れる箇所を 1 件とする。サ変可能の名詞は `する` が続くときだけ発話動詞に該当する。主語に人名か人を表す語（`利用者`、`チーム`、`筆者`）を含む形、受け身が続く形（`型が宣言された。`）、引用の「と」が続く形（`文書が述べると書いた。`）、「が」と動詞の間に読点が入る形は除外する。

英語の the README states、the type carries を日本語の語に移した形である。日本語の技術文は所在と手段で受ける。既存コーパスのコミット題名 1954 本のうち 31 本がこの形で、同じ書き手の記事での出現は 0 件である。

| 直す前 | 直した後 |
|---|---|
| `frame_end が区間に含まれることを型の doc が名乗る。` | `frame_end が区間に含まれることを型の doc に書く。` |
| `位置を求める列と当てる列が別であることを検査が述べる。` | `位置を求める列と当てる列が別であることを検査で確かめる。` |
| `selector が運ぶ project_epoch` | `selector に含まれる project_epoch` |

既定の重み: 3.0

## S02 文頭の指示代名詞

文頭の「これ」「それ」に係助詞の「は」「も」が続く箇所を 1 件とする。複数を表す接尾辞の「ら」を挟む形も対象とする。文の途中の指示代名詞と、他の助詞が続く形（`これが`、`これを`、`これと`）は対象外。

検出する例: `これは`、`それらは`

文頭で前の文を受けて評価する調子は、英語の This is intentional. の運びに由来する。Sonnet の回答 14 本では文頭の「これは」「これも」が 9 回出現した。受ける名詞を書くか、評価を前の文に畳めば足りる。

| 直す前 | 直した後 |
|---|---|
| `これは意図的です。` | `型を分けたのは意図したものである。` |
| `これらは規則だ。` | `以上の 6 つを規則とする。` |

既定の重み: 1.0

## S03 説明の足場語

語リストの足場語が現れた箇所を 1 件とする。`重要なのは`、`要するに`、`正直に言うと`、`結論から言うと`、`言い換えれば`、`ポイントは`、`に他ならない` など 20 語を表層で照合する。`つまり` は読点が続く形だけに一致するので、`つまり何を直すか。` は対象外。

英語の説明文の足場（scaffolding）の直訳である。日本語の技術文は主張だけで成立する。人間側のコーパスにはこれらがほぼ現れず、外しても文が成立する。

| 直す前 | 直した後 |
|---|---|
| `重要なのは順序です。` | `順序で決まる。` |
| `つまり、設定を先に読む。` | `設定を先に読む。` |

既定の重み: 2.5

## S04 技術文の「私」

一人称の代名詞（`私`、`わたし`）に助詞の「は」「が」「の」「も」か「自身」が続く箇所を 1 件とする。`「私」を省く。` のように他の語が続く形は対象外。

責任の所在を明示する英語の癖で、日本語の技術文は書き手を明示しない。3 体の観察では 2 体が「私」を使い、1 体は 1 回も使わず、文意に差は無かった。主体を示す必要があるなら「こちらで」「今回は」「手元では」に置換する。

| 直す前 | 直した後 |
|---|---|
| `私が気づいて追加しました。` | `こちらで気づいて追加した。` |
| `これは私の設計判断であり` | `例外の型を分けたのは今回の判断で` |

既定の重み: 2.0

## S05 「ではなく」の対句

名詞句か断定の助動詞に「では」と連用形の「ない」が続く箇所と、対句を導く句を 1 件とする。連用形なので後ろに肯定が続く形だけに一致し、`設計は自明ではない。` のように述語で終わる形は対象外。

検出する例: `だけでなく`、`静的ではなく`

否定を先に置いて肯定を出す運びは英語の強調の型である。毎文に置くと、確信の強い主張と弱い主張を読み手が区別できない。要所に限れば有効である。

| 直す前 | 直した後 |
|---|---|
| `静かに失敗するのではなく、明示的に落とす。` | `エラーを返して落とす。` |
| `設定だけでなく引数も見る。` | `設定と引数の両方を見る。` |

既定の重み: 0.75

## S06 文頭の接続詞の連打

接続詞で始まる文が、段落や箇条書きの項目などの一区切りの中で改行を挟まずに 3 文以上続く範囲を 1 件とする。語リストの接続詞（`さらに`、`また`、`加えて`、`これにより`、`したがって`、`そのため`、`その結果`、`一方`、`ただし`、`なお`）が文の先頭に Token の境界で一致し、その直後で新しい節が始まる形だけが接続詞に該当する。`さらに直す。` のように語に述語や助詞が続く形は副詞の用法なので除外する。

検出する例: `さらに`、`また、`、`その結果、`

英語の接続詞を文ごとに置く運びを移した形である。日本語は主題の流れで文が繋がるので、接続詞を連ねると文と文の関係がかえって見えにくい。

| 直す前 | 直した後 |
|---|---|
| `さらに規則を数える。また、規則を並べる。したがって規則が残る。` | `規則を数えて並べると、残る規則が分かる。` |

既定の重み: 0.75

## L01 慣習語の和語化

語リストの句が表層で一致した箇所と、原形が語リストにある動詞（`濾す`、`掃く`）を 1 件とする。動詞は活用形を原形で吸収するので、`掃いた` と `掃く` の両方に一致する。句は文字列の一致なので、`窓を開ける。` のような普通の用法には反応しない。

検出する例: `品書き`、`設定の窓`、`旗を立てる`、`ソースから建てた`、`古いログを掃く`

語を選ぶ基準は、その分野の人がその語を使うかである。意味の合う語を辞書から選ぶと慣習から外れる。和語で言い換えた術語は、意味が通っても読み手の知る呼び名から外れ、その行だけ読む人に届かない。既存コーパスの表の語は、同じ書き手の記事に 1 件も出現しなかった。

| 直す前 | 直した後 |
|---|---|
| `品書き` | `メニュー` |
| `設定の窓` | `設定ウィンドウ` |
| `電文` | `メッセージ` |
| `設定の鍵` | `設定キー` |
| `旗を立てる` | `フラグを立てる` |
| `焦点の輪` | `フォーカスリング` |
| `ソースから建てる` | `ソースからビルドする` |
| `冷えた 1 回目` | `コールドスタート` |
| `骨を置く` | `雛形を置く` |
| `速い道` | `高速パス` |

既定の重み: 3.0

## L02 辞書の第一義と逐語訳

語リストの句が表層で一致した箇所と、数と助数詞（`つ`、`個`）に「の」が続き、名詞句の後に「を持つ」と語リストの機械（`マシン`、`環境`、`サーバー`、`ホスト`）が並ぶ範囲を 1 件とする。機械の語が無い `8つのワーカーを持つ設定だ。` と、読点で切れる形は除外する。

検出する例: `既定では`、`静かに失敗する`、`フォールバックとなります`、`8つのワーカーを持つマシン`

英語の語に辞書の第一義を当てた訳で、L01 と反対側の逸脱である。漢語なので硬い文には馴染むが、分野の慣習とは別の語になる。

| 直す前 | 直した後 |
|---|---|
| `既定では無効だ。` | `デフォルトでは無効だ。` |
| `書き込みは静かに失敗します。` | `書き込みはエラーにならずに失敗します。` |
| `決済失敗を経験する。` | `決済に失敗する。` |
| `8つのワーカーを持つマシン` | `8 ワーカー構成のマシン` |
| `上流へのフォールバックとなります。` | `上流にフォールバックします。` |
| `上限に丸められる。` | `上限で頭打ちになる。` |
| `直感的な意味論` | `分かりやすい振る舞い` |

既定の重み: 2.0

## L03 英語のリズムの直写

動詞に `始める` が続く箇所（接続助詞を 1 つ挟む形も含む）と、動詞に過去の `た` と `瞬間` が続く箇所を 1 件とする。原形で照合するので、`失敗しはじめた` のような仮名の表記にも一致する。`作業を始める。` のように動詞が前に無い形は対象外。

検出する例: `失敗し始める`、`一杯になった瞬間`

英語の begin to と the moment を語の順のまま写した形である。日本語は状態の変化を「〜すると」「〜した時点で」で受ける。人間側は 1000 字あたり 0.1 件で普通の用法、Claude の散文は 0.6〜0.8 件で判別に効く。

| 直す前 | 直した後 |
|---|---|
| `一杯になった瞬間、書き込みは静かに失敗し始めます。` | `一杯になると、書き込みはエラーにならずに失敗します。` |
| `実行した瞬間に落ちる。` | `実行すると落ちる。` |

既定の重み: 3.0

## D01 短文の連打

検出する例: `窓が開く。鍵が回る。値が減る。`

日本語の文字数が 15 以下で句点で終わる文が、同じ一区切りの中で改行を挟まずに 3 文以上続く範囲を 1 件とする。箇条書きの項目と表のセルは別の一区切りなので、またいで連打に数えない。文字数は日本語の文字だけを数えるので、`JSON と CSV と TOML の値を返す。` は短文に該当する。

短文の連打は翻訳文学の手触りになる。ジャンルで件数が変動し、人間の文にも同程度に出るので重みは低い。

| 直す前 | 直した後 |
|---|---|
| `窓が開く。鍵が回る。値が減る。` | `窓が開いて鍵が回ると、値が減る。` |

既定の重み: 0.5

## D02 述語を持たない短い断片文

句点で終わり、日本語の文字数が 7 以下で、述語（動詞、形容詞、形状詞、助動詞の だ と です）を 1 つも持たない文を 1 件とする。句点で終わらない見出しと箇条書きの項目は対象外で、`9月10日に日本を出発。` のように 7 字を超える断片も数えない。

簡潔さは語数の少なさではない。助詞と主題を削った断片は、読み手が文脈を全部持っている前提でしか解けない。人間の Rust コメントと Claude 側で 1000 字あたりの件数が重なり、判別にほとんど効かないので重みは 0.1 である。

| 直す前 | 直した後 |
|---|---|
| `名詞の列挙。` | `名詞を列挙する。` |
| `出どころ。` | `値の出どころを示す。` |

既定の重み: 0.1

## D03 無根拠の緩和と譲歩

敬体率が 0.5 以上の文書で、緩和の並びが現れた箇所を 1 件とする。`かもしれない`、意志推量形の `だろう`、`と思われる`、`と考えられる`、`可能性がある`、`と言えるでしょう`、`はずです` を原形で照合するので、`かもしれません` と `と考えられました` にも一致する。常体の文書では適用しない。

検出する例: `かもしれません`、`だろう`、`と思われます`、`可能性があります`、`と言えるでしょう`、`はずです`

全文に譲歩と条件付けを付けると、確信のある判断とない判断の区別が消える。14 回答のうち 12 に譲歩か条件付けがあり、告白と事後の正当化が同じ型で語られていた。根拠が本文にあるなら言い切り、不確実なら何が不確実かを書く。

| 直す前 | 直した後 |
|---|---|
| `壊れる可能性があります。` | `入力が 1 万字を超えると壊れます。` |
| `直るはずです。` | `直ります。` |

既定の重み: 0.75

## R01 敬体の文書に混じる口語

敬体率が 0.5 以上の文書で、語リストの口語が表層で一致した箇所を 1 件とする。常体の文書では適用しない。

検出する例: `ちょっと`、`やつ`、`みたいな`、`てしまいました`

報告書と仕様の語彙から外れた語で、敬体の文に混ざると読み手への距離が揺れる。敬体のブログでは `ちょっと` が普通に出るので重みは 1.0 である。

| 直す前 | 直した後 |
|---|---|
| `ちょっと直します。` | `少し直します。` |
| `規則みたいな形です。` | `規則のような形です。` |
| `消してしまいました。` | `削除しました。` |

既定の重み: 1.0

## R02 身体的な比喩

語リストの比喩が表層で一致した箇所を 1 件とする。敬体と常体のどちらの文書でも適用する。

検出する例: `元のファイルは無傷`、`ホバーの手応え`、`優雅に終了する`

英語の技術文は身体的な比喩を平常の温度で使うが、日本語の技術文は抽象語で書く。温度の高い語が残ると、事実の記述と書き手の感想の境が曖昧になる。

| 直す前 | 直した後 |
|---|---|
| `元のファイルは無傷です。` | `元のファイルは変更しません。` |
| `ホバーの手応え` | `ホバー時の反応` |
| `優雅に終了する。` | `正常に終了する。` |

既定の重み: 2.0

## R03 敬体と常体の混在

敬体率と常体率がともに 2 割以上の文書を 1 件とする。分母は句点で終わる文で、見出しと体言止めは分母に入らない。文末の助動詞に です か ます を含む形と、`ください` で終わる形を敬体に数えるので、`確認してください。` の並ぶ手順は混在に該当しない。

語調は読み手で決まる。利用者向けの案内と記事は敬体、内部の設計文書とコミットは常体で、一つの文書の中で揺れると読み手が別の声を受け取る。人間側で出現したのは README の 1 件だけである。

| 直す前 | 直した後 |
|---|---|
| `規則を数えます。規則を並べる。` | `規則を数えます。規則を並べます。` |

既定の重み: 2.0

## G01 文末の述語の和語率

文末の述語が 10 個以上あり、和語の動詞の割合が 0.70 を超える文書を 1 件とし、その和語の動詞を頻度順に列挙する。
