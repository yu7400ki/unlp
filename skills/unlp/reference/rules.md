# 規則

検出器が数える規則について、規則 ID ごとに節を分けて記述する。見出しは指摘の規則 ID から引ける形にし、検出器のコードは説明を持たずにここの見出しを参照する。

## 層と採点

規則は 6 つの層に分かれ、層が重みと計数の条件を決める。

| 層 | 規則 | 数えるもの | 性質 |
|---|---|---|---|
| 構造 | S01〜S06 | 無生物主語と発話動詞、文頭の指示代名詞、足場語、書き手の明示、否定と肯定の対句、文頭の接続詞の連打 | 指示でもモデルでも残る |
| 語彙 | L01〜L03 | 慣習語からの逸脱。和語化の側と漢語・逐語訳の側 | 語リストに依存する |
| 密度 | D01〜D03 | 短文の連打、述語を持たない断片文、人間の文に普通の表現の欠如 | ジャンルで変動する |
| レジスター | R01〜R03 | 口語の混入、身体的な比喩、敬体と常体の混在 | 敬体率で適用を切り替える |
| 定型句 | F01〜F04 | 太字、2 倍ダッシュと矢印、空虚な強調 | 表層で確実に検出できる |
| 語種 | G01 | 文末の述語に占める和語動詞の割合 | 文書単位の割合 |

癖には二つの層がある。語彙と装飾と分量の層は、指示とモデルで両極に変動する。指示の無い Sonnet は漢語と冗長さの方向に、簡潔の指示を受けた Opus と Fable は和語と断片文の方向に逸脱する。どちらも日本語話者の文から外れ、向きが正反対である。しかし構造の層は指示とモデルに依存しない。文書や型を語り手に立てる形、文頭で前の文を受けて評価する形、足場語、書き手の明示、場面によらない一つの声は、どの観察にも共通して出現した。したがって構造の層（S）を最優先で直し、語彙の層（L）は両極を同時に検出する。簡潔の指示だけを与えても、和語の断片文という別の不自然さに変わるだけである。

点は、指摘 1 件に規則ごとの重みを乗じ、日本語の文字数 1000 字あたりに正規化した値である。層ごとの小計と規則ごとの件数も併せて出力する。日本語の文字数が 300 字に満たない入力では、1 件の指摘で点が数十動き、割合で評価する意味が無い。この下限に満たない入力は件数で判断して、構造か語彙の層の指摘が 1 件でもあれば超過として扱う。密度・レジスター・語種の文書単位の規則は、下限以上の入力にだけ適用する。

悪い例はコードスパンに置く。検出器はコードスパンの中身を採点の対象から外すので、規則集が自身の例を数えることはない。表のセルで外れるのは太字と矢印と述語の無いセルだけなので、表に置く例もコードスパンで囲む。

## S01 文書・型・テストを語り手にしない

人を表さない名詞に格助詞の「が」が続き、挟む語が 6 語以内で語リストの発話動詞（`述べる`、`名乗る`、`名指す`、`語る`、`答える`、`主張`、`宣言`、`約束`、`教える`、`訴える`）が現れる箇所を 1 件とする。サ変可能の名詞は `する` が続くときだけ発話動詞に該当する。主語に人名か人を表す語（`利用者`、`チーム`、`筆者`）を含む形、受け身が続く形（`型が宣言された。`）、引用の「と」が続く形（`文書が述べると書いた。`）、「が」と動詞の間に読点が入る形は除外する。

英語の the README states、the type carries を日本語の語に置き換えた形である。日本語の技術文は、例えば `README に書く`、`検査で確かめる` のように所在と手段で受ける。既存コーパスのコミット題名 1954 本のうち 31 本がこの形で、同じ書き手の記事での出現は 0 件である。

| 直す前 | 直した後 |
|---|---|
| `frame_end が区間に含まれることを型の doc が名乗る。` | `frame_end が区間に含まれることを型の doc に書く。` |
| `位置を求める列と当てる列が別であることを検査が述べる。` | `位置を求める列と当てる列が別であることを検査で確かめる。` |
| `selector が運ぶ project_epoch` | `selector に含まれる project_epoch` |

デフォルトの重み: 3.0

## S02 文頭の指示代名詞

文頭の「これ」「それ」に係助詞の「は」「も」が続く箇所を 1 件とする。複数を表す接尾辞の「ら」を挟む形も対象とする。文の途中の指示代名詞と、他の助詞が続く形（`これが`、`これを`、`これと`）は数えない。

検出する例: `これは`、`それらは`

文頭で前の文を受けて評価する調子は、英語の This is intentional. の運びに由来する。Sonnet の回答によく出る形で、14 本では文頭の `これは`、`これも` が 9 回出現した。受ける名詞を書くか、評価を前の文にまとめればよい。

| 直す前 | 直した後 |
|---|---|
| `これは意図的です。` | `型を分けたのは意図したものである。` |
| `これらは規則だ。` | `以上の 6 つを規則とする。` |

デフォルトの重み: 1.0

## S03 説明の足場語

語リストの足場語が現れた箇所を 1 件とする。`重要なのは`、`要するに`、`正直に言うと`、`結論から言うと`、`言い換えれば`、`ポイントは`、`に他ならない` など 20 語を表層で照合する。`つまり` は読点が続く形だけに一致するので、`つまり何を直すか。` は数えない。

英語の説明文で足場（scaffolding）の役を果たす語の直訳である。日本語の技術文は主張だけで成立する。人間のコーパスにはこれらの語がほぼ現れず、外しても文が成立する。

| 直す前 | 直した後 |
|---|---|
| `重要なのは順序です。` | `順序で決まる。` |
| `つまり、設定を先に読む。` | `設定を先に読む。` |

デフォルトの重み: 2.5

## S04 技術文の「私」

一人称の代名詞（`私`、`わたし`）に助詞の「は」「が」「の」「も」か「自身」が続く箇所を 1 件とする。`「私」を省く。` のように他の語が続く形は数えない。

責任の所在を明示する英語の癖で、日本語の技術文は書き手を明示しない。3 体の観察では 2 体が `私` を使い、1 体は 1 回も使わず、文意に差は無かった。主体を示す必要がある際は「こちらで」「今回は」「手元では」に置換する。

| 直す前 | 直した後 |
|---|---|
| `私が気づいて追加しました。` | `こちらで気づいて追加した。` |
| `これは私の設計判断であり` | `例外の型を分けたのは今回の判断で` |

デフォルトの重み: 2.0

## S05 「ではなく」の対句

名詞句か断定の助動詞に「では」と連用形の「ない」が続く箇所と、対句を導く句を 1 件とする。連用形なので後ろに肯定が続く形だけに一致し、`設計は自明ではない。` のように述語で終わる形は数えない。

検出する例: `だけでなく`、`静的ではなく`

否定を先に置いて肯定を出す運びは英語の強調の型である。毎文に置くと、確信の強い主張と弱い主張の区別が難しくなる。要所に限れば有効である。

| 直す前 | 直した後 |
|---|---|
| `静かに失敗するのではなく、明示的に落とす。` | `エラーを返して落とす。` |
| `設定だけでなく引数も見る。` | `設定と引数の両方を見る。` |

デフォルトの重み: 0.75

## S06 文頭の接続詞の連打

接続詞で始まる文が、段落や箇条書きの項目などの一区切りの中で改行を挟まずに 3 文以上続く範囲を 1 件とする。語リストの接続詞（`さらに`、`また`、`加えて`、`これにより`、`したがって`、`そのため`、`その結果`、`一方`、`ただし`、`なお`）が文の先頭に Token の境界で一致し、その直後で新しい節が始まる形だけが接続詞に該当する。`さらに直す。` のように語に述語、助詞、助動詞、接尾辞が続く形は接続詞の用法でないので除外する。

検出する例: `さらに`、`また、`、`その結果、`

英語の接続詞を文ごとに置く運びを持ち込んだ形である。日本語は主題の流れで文が繋がるので、接続詞を連ねていくと文と文の関係がかえって見えにくくなる。

| 直す前 | 直した後 |
|---|---|
| `さらに規則を数える。また、規則を並べる。したがって規則が残る。` | `規則を数えて並べると、残る規則が分かる。` |

デフォルトの重み: 0.75

## L01 慣習語の和語化

語リストの句が表層で一致した箇所と、原形が語リストにある動詞（`測る`、`繋ぐ`、`畳む`、`寄せる`、`突き合わせる`、`効く`、`落とす` など 24 語）と名詞（`篩`、`素通し`、`持ち越し`、`物差し` など 12 語）を 1 件とする。動詞は活用形を原形で吸収するので、`測った` と `測る` の両方に一致する。語リストの慣用句（`型が効`、`補完が効`、`に落と` など）と重なる語は数えないので、`型が効いている。` と `仕様をコードに落とす。` は対象外で、`設定が効いている。` と `末尾の空白を落とす。` は対象になる。原形で照合する語は、人間の技術文に慣用句の外でほとんど出現しない語に限る。`足す`、`引く`、`捨てる`、`積む` のように人間も同じ意味で使う語は列挙しない。`窓` や `道` のように普通の文章にも出る語は句で照合するので、`窓を開ける。` のような普通の用法には反応しない。

検出する例: `品書き`、`設定の窓`、`旗を立てる`、`ソースから建てた`、`古いログを掃く`、`実行時間を測る`、`エラーを黙って返す`、`検証を掛ける`

語を選ぶ基準は、その分野の人がその語を使うかである。意味の合う語を辞書から選ぶと慣習から外れる。和語で言い換えた術語は、読み手の知る呼び名から外れる。読み手が `メニュー`、`フラグ` と呼ぶものを `品書き`、`旗` と書くと、意味は通っても、その行だけ読む人に届かない。既存コーパスの表の語は、同じ書き手の記事に 1 件も出現しなかった。

| 直す前 | 直した後 |
|---|---|
| `品書き` | `メニュー` |
| `設定の窓` | `設定ウィンドウ` |
| `設定の鍵` | `設定キー` |
| `旗を立てる` | `フラグを立てる` |
| `焦点の輪` | `フォーカスリング` |
| `ソースから建てる` | `ソースからビルドする` |
| `冷えた 1 回目` | `コールドスタート` |
| `骨を置く` | `雛形を置く` |
| `速い道` | `高速パス` |
| `実行時間を測る` | `実行時間を計測する` |
| `サーバーに繋ぐ` | `サーバーに接続する` |
| `エラーを黙って返す` | `エラーを出さずに返す` |
| `素通しにする` | `パススルーにする` |

デフォルトの重み: 3.0

## L02 辞書の第一義と逐語訳

語リストの句が表層で一致した箇所と、数と助数詞（`つ`、`個`）に「の」が続き、名詞句の後に「を持つ」と語リストの機械（`マシン`、`環境`、`サーバー`、`ホスト`）が並ぶ範囲と、原形が語リストの術語（`既定`、`経路`、`照合`、`実測`、`電文`、`節点`、`要求`、`応答` など 17 語）にある名詞を 1 件とする。機械の語が無い `8つのワーカーを持つ設定だ。` と、読点で切れる形は除外する。術語は、`時間を実測する。` のように「する」が続く動詞の用法と、語リストの複合語（`逐語訳`、`要求仕様`、`終了要求`、`線形応答`、`応答性`）と重なる形を除外する。人間の技術文は `要求` と `応答` を複合語の一部として使い、Claude は `次の要求が` のように単独の名詞として使う。`検査` は人間の技術文も単独の名詞として使うので列挙しない。

検出する例: `既定では`、`静かに失敗する`、`フォールバックとなります`、`8つのワーカーを持つマシン`、`既定値`、`経路の往復`

英語の語に辞書の第一義を当てた訳で、L01 と反対の向きの逸脱である。漢語なので硬い文には馴染むが、分野の慣習とは別の語になる。人間の技術文は英語の術語をカタカナ語で書く。例えば人間のコーパスでは `既定` が 0 件に対して `デフォルト` が 40 件、`照合` が 0 件に対して `マッチ` が 6 件だった。

| 直す前 | 直した後 |
|---|---|
| `既定では無効だ。` | `デフォルトでは無効だ。` |
| `書き込みは静かに失敗します。` | `書き込みはエラーにならずに失敗します。` |
| `決済失敗を経験する。` | `決済に失敗する。` |
| `8つのワーカーを持つマシン` | `8 ワーカー構成のマシン` |
| `上流へのフォールバックとなります。` | `上流にフォールバックします。` |
| `上限に丸められる。` | `上限で頭打ちになる。` |
| `直感的な意味論` | `分かりやすい振る舞い` |
| `既定値を使う。` | `デフォルト値を使う。` |
| `経路を返す。` | `パスを返す。` |
| `節点を辿る。` | `ノードを辿る。` |
| `実測で決める。` | `計測で決める。` |

デフォルトの重み: 2.0

## L03 英語のリズムの直写

動詞に `始める` が続く箇所（接続助詞を 1 つ挟む形も含む）と、動詞に過去の `た` と `瞬間` が続く箇所を 1 件とする。原形で照合するので活用形（`し始めた`、`し始めます`）に一致する。`作業を始める。` のように動詞が前に無い形は対象外。

検出する例: `失敗し始める`、`一杯になった瞬間`

英語の begin to と the moment を語の順のまま訳した形である。日本語は状態の変化を「〜すると」「〜した時点で」で受ける。人間の文は 1000 字あたり 0.1 件で普通の用法だが、Claude の散文は 0.6〜0.8 件で判別に有効である。

| 直す前 | 直した後 |
|---|---|
| `一杯になった瞬間、書き込みは静かに失敗し始めます。` | `一杯になると、書き込みはエラーにならずに失敗します。` |
| `実行した瞬間に落ちる。` | `実行すると落ちる。` |

デフォルトの重み: 3.0

## D01 短文の連打

日本語の文字数が 15 以下で句点で終わる文が、同じ一区切りの中で改行を挟まずに 3 文以上続く範囲を 1 件とする。箇条書きの項目と表のセルは別の一区切りなので、またいで連打に数えない。文字数は日本語の文字だけを数えるので、例えば `JSON と CSV と TOML の値を返す。` は短文に数える。

検出する例: `窓が開く。鍵が回る。値が減る。`

短文の連打は翻訳文学の手触りになる。しかし件数はジャンルによって変わり、人間の文にも同程度に出るので重みは低い。

| 直す前 | 直した後 |
|---|---|
| `窓が開く。鍵が回る。値が減る。` | `窓が開いて鍵が回ると、値が減る。` |

デフォルトの重み: 0.5

## D02 述語を持たない短い断片文

句点で終わり、日本語の文字数が 7 以下で、述語（動詞、形容詞、形状詞、助動詞の だ と です）を 1 つも持たない文を 1 件とする。句点で終わらない見出しと箇条書きの項目、`9月10日に日本を出発。` のように 7 字を超える断片は数えない。

簡潔さは語数の少なさではない。助詞と主題を削った断片は、読み手が文脈を全部持っている前提でしか解けない。人間の Rust コメントと Claude の文で 1000 字あたりの件数が重なり、判別にほとんど寄与しないので重みは 0.1 である。

| 直す前 | 直した後 |
|---|---|
| `名詞の列挙。` | `名詞を列挙する。` |
| `出どころ。` | `値の出どころを示す。` |

デフォルトの重み: 0.1

## D03 人間の文に普通の表現の欠如

本文と表のセルの日本語が 1000 字以上の文書で、次の 9 表現を合わせた件数が 1000 字あたり 1.00 件を下回る文書を 1 件とし、抜粋にその件数を表示する。コードのコメントと文字列、コミットメッセージは分子と分母の両方から除外する。

- `〜ようになる`、`〜ていく`、`について`、`例えば`、`と呼ぶ`（`と呼ばれる` を含む）
- 接続詞の `しかし`、副詞の `よく`、`難しい` と `簡単`、名詞の `際`

原形と品詞の並びで判定するので、`性能がよくなる` の形容詞の `よく` と、`登録すると呼ばれる` の接続助詞の `と` は数えない。

人間の技術記事と文書は、例を挙げ、話題を示し、語を定義し、変化と対比を述べる際にこれらの表現を普通に使う。較正に使った 1000 字以上の文書では、値の中央値が人間の技術記事と文書で 4.00 件、Claude の回答、README とスキル、設計文書、ADR で 0.00 件である。個々の表現は単独では自然な日本語なので、語として列挙しても指摘にならない。欠如は文書全体の割合としてのみ観察できる。ソースコードのコメントでは人間と Claude の値が重なるので対象から除外する。短い文書では 1 件の有無で値が大きく動くので、1000 字に満たない文書は判定しない。指摘は 1 文書に 1 件だけで、点への寄与は 1000 字の文書で最も大きい。この規則だけで加わる点を 1 点までに抑えるため、重みは 1.0 とする。

名詞と記号で済ませた説明を文として記述する。項目の列挙には具体例を添え、術語は初出で定義し、手順の前後で何が変わるかを明記する。表現だけを差し込んでも、説明の運びは改善しない。

| 直す前 | 直した後 |
|---|---|
| `遅延読み込み。初回アクセス時に展開。` | `初回にアクセスした際に展開する。この方式を遅延読み込みと呼ぶ。` |
| `キャッシュ導入で 2 回目以降が高速化。` | `キャッシュを入れると、2 回目以降は速く読めるようになる。` |
| `設定の優先順位: 引数 > 環境変数 > ファイル` | `設定は引数、環境変数、ファイルの順に優先する。例えば引数で渡した値は環境変数より優先する。` |

デフォルトの重み: 1.0

## R01 敬体の文書に混じる口語

敬体率が 0.5 以上の文書で、語リストの口語が表層で一致した箇所を 1 件とする。常体の文書では適用しない。

検出する例: `ちょっと`、`やつ`、`みたいな`、`てしまいました`

報告書と仕様の語彙から外れた語で、敬体の文に混ざると読み手への距離が揺れる。敬体のブログでは `ちょっと` が普通に出るので重みは 1.0 である。

| 直す前 | 直した後 |
|---|---|
| `ちょっと直します。` | `少し直します。` |
| `規則みたいな形です。` | `規則のような形です。` |
| `消してしまいました。` | `削除しました。` |

デフォルトの重み: 1.0

## R02 身体的な比喩

語リストの比喩が表層で一致した箇所を 1 件とする。敬体と常体のどちらの文書でも適用する。

検出する例: `元のファイルは無傷`、`ホバーの手応え`、`優雅に終了する`

英語の技術文は身体的な比喩を平常の温度で使うが、日本語の技術文は抽象語で書く。温度の高い語が残ると、事実の記述と書き手の感想の境が曖昧になる。

| 直す前 | 直した後 |
|---|---|
| `元のファイルは無傷です。` | `元のファイルは変更しません。` |
| `ホバーの手応え` | `ホバー時の反応` |
| `優雅に終了する。` | `正常に終了する。` |

デフォルトの重み: 2.0

## R03 敬体と常体の混在

敬体率と常体率がともに 2 割以上の文書を 1 件とする。分母は句点で終わる文で、句点の無い見出しは分母に入らない。文末の助動詞に です か ます を含む形と、`ください` で終わる形を敬体に数えるので、`確認してください。` の並ぶ手順は混在にならない。

語調は読み手で決まる。利用者向けの案内と記事は敬体、内部の設計文書とコミットは常体で、一つの文書の中で揺れると読み手が別の声を受け取る。人間の文で出現したのは README の 1 件だけである。

| 直す前 | 直した後 |
|---|---|
| `規則を数えます。規則を並べる。` | `規則を数えます。規則を並べます。` |

デフォルトの重み: 1.0

## F01 冒頭の太字の結論

文頭から始まる太字のうち、内側が 2 字以上 30 字以下で、句点で閉じるか末尾の Token が助動詞である箇所を 1 件とする。`**名詞の列挙**だ。` のように言い切っていない太字、文の途中の太字、対になっていない記法は数えない。同じ箇所を F02 も数えるので、実効の重みは両者の和になる。

回答の冒頭に結論を太字で置くのは英語の回答の型で、結論は文の順序で示せば足りる。人間のコーパスでの出現は 0 件である。

| 直す前 | 直した後 |
|---|---|
| `**意図したものです。** 置き換えても動作は変わりません。` | `置き換えても動作は変わらないので、意図したものです。` |

デフォルトの重み: 2.0

## F02 本文の太字

太字で囲んだ箇所を 1 件とする。文頭の太字にコロンが続く定義の列の見出し（`- **項目**: 説明`）と、中身が空白だけの太字は数えない。句点で終わらない、太字だけでできた一区切り（`**参考文献**`）は見出しの代わりなので数えず、句点で終わる文を太字で囲んだ一区切り（`**結論です。**`）は数える。コードスパンの中の `**` と、対になっていない `**` は太字に該当しない。表のセルの太字は抽出の段で外すので、セルの中の強調も数えない。

英語の技術文書の装飾で、日本語の本文と Rust の doc コメントでは浮く。強調は語の選択と文の位置で示す。人間の README は定義の列に太字を普通に使うため、文頭の太字にコロンが続く形と、太字の内側の末尾がコロンで終わる形を除外している。除外の前は人間の README が 54.8 点になった。人間の技術記事と教材も強調に太字を使う（1000 字あたり 0〜1.3 件）が、Claude が長期のプロジェクトで書いた ADR と設計文書では 21〜24 件になるので重みは 2.0 である。

| 直す前 | 直した後 |
|---|---|
| `**重要な点**を落とさない。` | `落とせない点が 1 つある。` |

デフォルトの重み: 2.0

## F03 2 倍ダッシュと矢印

ダッシュと矢印が現れた箇所を 1 件とする。2 倍ダッシュ（`——`）は 2 字で 1 件、単独のダッシュ（`—`）と矢印（`→`）はそれぞれ 1 件で、抜粋は前後 10 字を添える。表のセルの矢印は抽出の段で空白に置換するので数えない。

英語の技術文書の記法である。日本語では挿入を括弧か句点で切り、矢印は表とコードに限る。人間のコミットは置換の記法（`値 → データ型`）に矢印を使う（1000 字あたり 1.5 件）ので重みは 2.0 で、Claude の設計文書と散文で点を支える項目になる。

| 直す前 | 直した後 |
|---|---|
| `設計——実装の順だ。` | `設計（実装の前）の順だ。` |
| `入力→出力に変える。` | `入力を出力に変える。` |

デフォルトの重み: 2.0

## F04 空虚な強調

語リストの強調の語が表層で一致した箇所を 1 件とする。

検出する例: `非常に`、`極めて`、`不可欠`、`根本的な`、`包括的`

内容を追加せずに文を長くする語である。程度は数で書き、必要かどうかは条件で書く。Wikipedia にも 1000 字あたり 0.18 件出るので重みは 1.0 である。

| 直す前 | 直した後 |
|---|---|
| `非常に短い。` | `3 割短い。` |
| `順序が不可欠だ。` | `順序を変えると壊れる。` |

デフォルトの重み: 1.0

## G01 文末の述語の和語率

文末の述語が 10 個以上あり、和語の動詞の割合が 0.70 を超える文書を 1 件とし、その和語の動詞を頻度順に列挙する。ここで述語と呼ぶのは、句点で終わる文の末尾から助動詞・助詞・記号・非自立可能の Token を飛ばした先の語である。和語の動詞と、サ変可能の名詞に `する` か `できる` が続く述語の合計を分母に取る。文末の述語が 10 個未満の文書は判定しない。超過の大きさは点に反映せず、他の指摘と同じ 1 件として数える。抜粋には原形と出現数を 10 語まで載せる。

`動く`、`比べる` のような普通の和語動詞は、単独では自然な日本語なので語として列挙できない。慣習的なサ変動詞が和語に置き換わる癖は、文書全体の割合としてのみ現れる。和語化は述語に集中する。文末の和語率は、人間の Rust コメントで 0.19、Wikipedia の技術記事で 0.42、利用者のブログで 0.57 に対して、Claude のコーパスでは 0.81〜0.97 になり、動詞全体の和語率よりも分離が大きい。日本語の文は述語で終わり、読み手は文末の語で文の調子と分野を受け取る。和語動詞は多義で、何をしたかを文脈に預けるので、その行だけ読む人（コミット題名や doc コメントの読み手）には意味を取るのが難しい。

| 直す前 | 直した後 |
|---|---|
| `代表値が variant を網羅することを固定する。` | `代表値が variant を網羅することを検証する。` |
| `名前で指す読み取りを core の上に組む。` | `名前で指す読み取りを core 上に実装する。` |
| `候補の練り直しが切のときは働きません。` | `候補の再計算がオフのときは動作しません。` |

列挙された語をすべて置換する必要はない。`使う`、`決める` のように分野の慣習に収まる語は残し、`引く`、`移す`、`縛る`、`落ちる` のように意味を文脈に預ける語から置換する。

デフォルトの重み: 2.0
